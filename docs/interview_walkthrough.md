# 面试讲解与演示路线

这个项目解决的是运动时腕部光学心率估计容易被伪影干扰的问题。我把 PPG 作为主要脉搏信息来源，把三轴加速度作为运动参考，实现了从官方数据读取、窗口处理、传统算法、神经网络训练到评估和 ONNX 推理的完整流程。它是我独立实现的算法工程作品，重点是代码、实验流程和问题分析，没有宣称精确复现某篇论文的最终指标。

我先做了 Welch 频谱峰值法，作为容易解释的基线；再用 ACC 频谱降低运动相关峰的评分，并实现连续多参考 NLMS。NLMS 每个受试者重新初始化，连续样本只更新一次，避免重叠窗口导致重复学习。它并不总能改善结果，因为 ACC 不是纯噪声参考，当运动频率与脉搏频率接近时，也可能去掉有用成分。因此我保留差的结果，而不是只展示成功案例。

深度学习部分用轻量残差 TCN。PPG 分支接收 64Hz 的 512 个点，ACC 分支接收 32Hz 的 256 个点，分别提取时间特征后融合。这样能保留各传感器原生采样率，不必为了模型输入强行把全部信号重采样到一样长。PPG-only 模型提供单模态比较。双分支模型参数更多，所以实验能说明这个实现组合的表现，不能单凭分数证明收益全部来自 ACC。

我按受试者划分训练、验证和测试，先用一名独立测试受试者跑通端到端管线，再采用相同配置做固定 LOSO。PPG 在各窗内标准化，ACC 的公共尺度和目标心率尺度只从当前训练受试者拟合；验证集选 checkpoint，测试集不参与调参。推理接口只有 PPG/ACC，ECG、R 峰、心率和活动标签不能进入模型。评估保留全部窗口，记录 MAE、RMSE、每位受试者和不同活动下的误差，以及 coverage。

最初我对标签做过比较深入的审计，发现了一些重复峰和重建差异，相关证据都保留了。后来根据项目目的收敛了范围：直接用官方发布的 HR 标签，把历史生成器考证延期，但时间对应、文件身份、标签数和数据隔离继续检查。这样既不把求职作品变成长期论文考证，也不因为改了定位就放松基本实验可靠性。

最后我把首折模型导出为 ONNX，在 CPU 上检查动态 batch 的输出与 PyTorch 是否一致。模型输入仍是经过相同预处理和训练尺度归一化后的窗口，所以测得的模型推理时间不等于可穿戴设备的完整输出延迟。目前是离线零相位滤波和对称卷积，不会将其包装为已经实现实时手表部署。

演示时先展示英文 README 的实测结果表和三张汇总图，再运行无真实数据也可工作的合成 demo，解释心率与运动邻频/同频时的差异，最后运行本地 ONNX smoke。具体指标以 [当前报告](showcase_results.md) 为准，讲清已经完成的分母、固定配置和失败条件，不背文献最优分数。若公司询问下一步，我会优先提因果处理、容量匹配/ACC-only 消融、多 seed 和更强运动伪影基线；这些是后续工作，不说成已经完成。
